# Доступ, роли, промокоды

Бот продаёт подписку. Пока платежей нет: роли выдаёт админ — промокодом или по Telegram ID.

## Роли

| роль | что видит | ключ |
|---|---|---|
| Подписка не активна | только главное меню и свой профиль с кнопкой покупки | `none` |
| Воркер | все отрисовки, кроме VAC | `worker` |
| Чаттер | все отрисовки + VAC | `chatter` |
| Админ | всё + админ-панель | `admin` |

Роли выстроены по уровню: `none < worker < chatter < admin`, проверка — «не ниже нужной».
Админ включает всё, что умеют младшие.

## Гейт

Проверка стоит второй в цепочке middleware — сразу за капчей, до всех обработчиков. Поэтому новый
раздел нельзя открыть, забыв про проверку: достаточно, чтобы он был кнопкой.

```
нажатие кнопки
   ↓
капча пройдена? ──нет──▶ карточка капчи / пауза
   ↓ да
публичный callback? ──да──▶ обработчик
   ↓ нет
роль ≥ нужной? ──нет──▶ всплывающее окно, экран не меняется
   ↓ да
обработчик
```

Публичные callback: `root_menu`, `access_profile`, `access_buy`, всё с префиксом `captcha_`.
Отдельные ветки: `admin_*` и `access_admin` — только админ; `cs2_vac` — «Чаттер» и выше.

Текст окна отказа:

```
Доступ закрыт: подписка не активна. Открой «👤 Профиль» — там статус и покупка.
```

Команды `/tracker` и `/emoji` проверяют доступ сами (это не callback): трекер — от «Воркера»,
`/emoji` — только админ.

## Профиль

Кнопка `👤 Профиль` — серая, отдельным длинным рядом под всеми кнопками главного меню.

```
👤 Профиль
Роль: Воркер
Подписка до: 02.12.2026 18:40 МСК
ID: 123456789

[💳 Купить подписку]   ← только когда роль не активна
[🛡 Админ-панель]      ← только админу
[🏠 Меню]
```

`💳 Купить подписку` — заглушка: нажатие только закрывает «часики», экран не меняется.

Если подписка истекла:

```
Роль: Подписка не активна
Была роль Воркер, истекла 01.12.2026 10:00 МСК
```

Срок проверяется лениво, при каждом обращении к роли: таймера нет, истёкшая запись просто
перестаёт считаться активной.

## Промокоды

Активация — командой в чате:

```
/promo WORK-ABC123
```

Ответ — карточка профиля с результатом: `Код принят · роль · до какого числа`. Ошибки: `Такого кода
нет`, `Ты уже активировал этот код`, `Код уже использован`.

Правила:

- код нормализуется: обрезаются пробелы, буквы приводятся к верхнему регистру;
- один пользователь — одна активация кода;
- по умолчанию код одноразовый (`PROMO_MAX_USES` меняет лимит для всех новых кодов);
- код живёт до удаления из админки, отдельного срока у кода нет;
- длина кода — до 20 символов (`PROMO_CODE_MAX`).

## Админ-панель

```
🛡 Админ-панель
[🎟 Создать промокод]   роль → срок → код (или «🎲 Случайный»)
[👤 Выдать роль по ID]  ID → роль → срок
[🛡 Выдать админку]     ID → бессрочно
[🗂 Промокоды]          список: код · роль · срок · использований
[← Назад]
```

Срок везде выбирается кнопками: `7 дней`, `30 дней`, `90 дней`, `∞ Навсегда`.

Список промокодов даёт удаление одной кнопкой на код; удалённый код перестаёт приниматься сразу.

## Хранение

`data/access.json` (каталог — `ACCESS_DATA_DIR`):

```json
{
  "users": {
    "123456789": { "role": "chatter", "until": 1795000000, "grantedBy": "999", "grantedAt": 1794000000 }
  },
  "promos": {
    "CHAT-ABC123": { "role": "chatter", "days": 30, "maxUses": 1, "usedBy": ["123456789"], "createdBy": "999", "createdAt": 1794000000 }
  }
}
```

Запись атомарная: временный файл и `rename`, как у трекера. Битый файл откладывается рядом
(`access.json.broken-<время>`), бот стартует с пустой базой.

## С чего начать: первая админка

Роль `admin` из `ADMIN_IDS` (список ID через запятую) действует всегда и не снимается — это
единственный способ войти в панель, когда промокодов ещё нет.

```yaml
environment:
  ADMIN_IDS: "123456789"
```

## Переменные

| ключ | по умолчанию |
|---|---|
| `ADMIN_IDS` | — (ID через запятую, роль админа вне файла) |
| `ACCESS_DATA_DIR` | `./data` (в контейнере `/app/data`) |
| `PROMO_MAX_USES` | 1 |
| `PROMO_CODE_MAX` | 20 |

## Что пока заглушки

- `💳 Купить подписку` — платежей нет, кнопка ничего не делает;
- `🛡 VAC` — кнопка и проверка доступа есть, шаблона экрана ещё нет: нажатие показывает
  «Шаблон VAC ещё не залит на сервер».
