# UX / UI спецификация

Документ описывает поведение и вид бота. Код не меняется: это карта, по которой потом режем.

## 1. Принципы

1. **Три уровня, не больше.** Меню → раздел → экран. Варианты (ПК/телефон) — четвёртый, но только там, где без них нельзя.
2. **Один экран — одно действие.** На каждом экране одна главная кнопка; остальные — служебные (`←`, `✖️ Отмена`).
3. **Меню живёт в одном сообщении.** Оно редактируется на месте, не плодит новые сообщения. Фото-меню — то же сообщение с подписью.
4. **Результат — всегда новое сообщение.** Скриншот не затирает меню: меню остаётся кнопками под ним.
5. **Ошибка называет причину и следующий шаг.** «Steam не отдал профиль» — плохо. «Steam ответил 429, это лимит по IP — повтори через минуту» — хорошо.
6. **Никаких тупиков.** Из любого состояния есть выход: `←` на уровень выше, `✖️ Отмена` — в начало.

Против нынешнего: восемь кнопок в ряд заменяются тремя, «Ошибка добавления» перестаёт быть плоским списком из трёх равнозначных пунктов, а Steam China уезжает к ошибкам, где ей место.

## 3. Навигация

- `🏠 Меню` — с любого уровня, всегда последняя кнопка в нижнем ряду.
- `←` — на уровень выше, сохраняет контекст раздела.
- `✖️ Отмена` — только пока бот ждёт ввода; возвращает туда, откуда пришли.
- Кнопка, которая уже нажата и не имеет смысла (например, «Уведомления: вкл», когда включены) — меняет подпись на противоположную, а не disappears.
- Переход в раздел — редактирование текущего сообщения; переход к экрану с фото (меню) — замена сообщения целиком.

## 4. Анатомия экрана

Меню-экран:

```
┌─────────────────────────────────────┐
│  [ фото-заставка раздела ]          │
│                                     │
│  <blockquote>🎭 Профиль             │
│  Что собрать?</blockquote>          │
│                                     │
│  [ 📨 Страница друга        ]       │
│  [ 📷 QR-страница           ]       │
│  [ 🫂 Ошибка добавления     ]       │
│  [ ⚠️ Ошибка браузера       ]       │
│  [ 🇨🇳 Steam China          ]       │
│  [ 🏠 Меню                  ]       │
└─────────────────────────────────────┘
```

Состояние ожидания:

```
┌─────────────────────────────────────┐
│  <blockquote>📨 Страница друга · ПК │
│  Отправь ссылку на фейк.</blockquote>│
│                                     │
│  [ ✖️ Отмена                ]       │
└─────────────────────────────────────┘
```

Результат:

```
┌─────────────────────────────────────┐
│  [ готовый скриншот ]               │
│                                     │
│  <blockquote>📨 Страница друга      │
│  Готово за 3.4 с.</blockquote>      │
│                                     │
│  [ 🔁 Ещё раз               ]       │
│  [ ➕ Добавить код друга    ]       │  ← только там, где применимо
│  [ 🏠 Меню                  ]       │
└─────────────────────────────────────┘
```

Правило подписи: первая строка — `раздел · вариант`, вторая — состояние. Больше двух строк в шапке не бывает.

## 5. Потоки

### 5.1 Генерация картинки

```
экран выбран
   ↓
[ЖДУ ССЫЛКУ]  «Отправь ссылку на фейк.»        кнопки: ✖️ Отмена
   ↓ ссылка
[ПРОВЕРКА]    http/https, публичный адрес      плохо → «Это не ссылка. Отправь адрес страницы.»
   ↓
[ПРОГРЕСС]    отдельное сообщение:
              «Читаю профиль…» → «Собираю картинку…»
   ↓
[РЕЗУЛЬТАТ]   фото + подпись + 🔁 / 🏠
```

### 5.2 Экран с кодом (CS2 Not Found, Dota, Steam China, ошибка добавления — телефон)

```
[ЖДУ ССЫЛКУ] → [ЧИТАЮ ПРОФИЛЬ] → [ЖДУ КОД] → [СБОРКА] → [РЕЗУЛЬТАТ]
```

Шаг кода всегда отдельным сообщением: старое удаляется, новое приходит с подсказкой формата (`ABCDE-FGHI`, до 32 символов).

### 5.3 CS2 Ban

```
[ЖДУ ССЫЛКУ] → [ЧИТАЮ ПРОФИЛЬ] → [ВЫБОР ВРЕМЕНИ] → [СБОРКА] → [РЕЗУЛЬТАТ]
                                      ↓ Custom
                                 [ЖДУ ТЕКСТ] → [СБОРКА]
```

После результата клавиатура времени остаётся: можно прогнать ту же ссылку другим сроком.

### 5.4 Трекер

```
📡 Трекер
├── [➕ Добавить]  → «Ссылка или SteamID64» → карточка «Следить?» → ✅ / ❌
├── [📋 Мои профили]
│     └── список: «🎮 Dota 2 · Ник»
│           └── карточка: 🔄 Обновить · 🗑 Отписаться · ← Назад
└── [🔔 Уведомления]  переключатель
```

## 6. Состояния

| состояние | что на экране | кнопки |
|---|---|---|
| `idle/меню` | фото раздела, подпись «Что собрать?» | разделы + 🏠 |
| `выбор варианта` | «Как открывать страницу?» | ПК · Телефон · ← |
| `ждём ссылку` | «Отправь ссылку на фейк.» | ✖️ Отмена |
| `читаю профиль` | «Читаю профиль…» | — |
| `ждём код` | «Отправь френд-код.» + пример | ✖️ Отмена |
| `сборка` | «Собираю картинку… 3 с» | — |
| `результат` | фото + «Готово за 3.4 с» | 🔁 · (➕ код) · 🏠 |
| `ошибка` | причина + что сделать | 🔁 · 🏠 |

## 7. Клавиатуры

Правила:

- не больше 6 кнопок на экране, из них 1 главная;
- главная — `style: primary`, разрушительная (`Отписаться`) — `style: danger`, служебные — без стиля;
- подпись до 32 символов, без точек в конце;
- по две кнопки в ряд — только когда они равнозначны (ПК/Телефон, 30 Mins/1 Hour).

Корневое меню:

```
[ 🎭 Профиль ]            [ 🎮 Коды ]
[ 📡 Трекер ]
```

## 8. Прогресс и обратная связь

- Пока идёт работа — `sendChatAction('upload_photo')`, чтобы в шапке чата шёл «отправляет фото».
- Прогресс-сообщение отдельное, обновляется по шагам, удаляется на результате.
- Если шаг занял больше 5 секунд, к тексту добавляется счётчик: «Собираю картинку… 7 с».
- Время сборки в подписи результата — оператору полезно видеть, где узкое место.

## 9. Ошибки

| причина | текст | кнопки |
|---|---|---|
| не http/https | «Это не ссылка. Нужен адрес страницы, начиная с http:// или https://.» | ✖️ |
| Steam 429 | «Steam ограничил запросы с сервера. Повтори через минуту.» | 🔁 · 🏠 |
| Steam отдал заглушку | «Steam вернул страницу-заглушку вместо профиля. Скорее всего блок по IP.» | 🔁 · 🏠 |
| профиль закрыт | «Профиль закрыт, данных нет. Нужен открытый профиль.» | ✖️ · 🏠 |
| CN-узел молчит | «Узел CN не ответил, страница уйдёт повтором. Ссылка уже создана.» | 🏠 |
| нет ключа API (трекер) | «На сервере не задан STEAM_WEB_API_KEY — статусы недоступны.» | 🏠 |
| шаблон отсутствует | «Экран не загружен на сервер: нет <файл>.» | 🏠 |
| неизвестная ошибка | «Сломалось на шаге «сборка». Подробности в логе сервера.» | 🔁 · 🏠 |

Правило: в тексте всегда есть либо причина, либо следующий шаг. Идеально — и то, и другое.

## 10. Трекер: уведомления

```
🎮 <b>Ник</b> начал играть в <b>Dota 2</b>
🟢 <b>Ник</b> в сети
⚫ <b>Ник</b> вышел из сети
```

Одна строка, без времени и ссылок: это лента событий, а не карточка. Переход в игру с игры той же — «теперь играет в …».

## 11. Тон и текст

- Обращение на «ты», глагол в повелительном: «Отправь ссылку», «Выбери экран».
- Названия разделов — существительные: «Профиль», «Коды», «Трекер».
- Точка в конце — только у предложений. У подписей кнопок точек нет.
- Эмодзи — один на раздел, не больше одного в подписи кнопки.
- Слово «фейк» остаётся: это внутренний жаргон операторов, менять на «страницу» не надо.

## 12. Ограничения Telegram, о которые упираемся

| что | лимит |
|---|---|
| подпись к фото | 1024 символа |
| текст кнопки | 64 символа (у нас ≤ 32) |
| `callback_data` | 64 байта |
| фото в сообщении | 10 МБ (наши до 3 МБ) |

## 13. Что это даёт

- В корне четыре кнопки вместо восьми — меньше поводов нажать не то.
- Один и тот же ритм: ссылка → прогресс → фото → «Ещё раз».
- Ошибки перестают быть безымянными.
- Всё, что видно, ложится в `data/ui.json`: подписи, эмодзи, стили, порядок. Дальше правки — без выкатки кода.

## 14. Что реализовано (as built)

Код приведён к этой карте. Точка входа для правок вида — `data/ui.json`, для правок логики — `src/bot.js`.

### 14.1 Разделы

| раздел | callback | клавиатура |
|---|---|---|
| 🎭 Профиль | `section_profile` | `profileKeyboard()` |
| 🎮 Коды | `section_codes` | `codesKeyboard()` |
| 📡 Трекер | `tracker_menu` | `trackerKeyboard()` |

`root_menu` возвращает логотип-меню (`replaceMenuWithPhoto`), разделы редактируют то же сообщение.

### 14.2 Три вида клавиатур под клавиатурой экрана

| вид | функция | что на ней |
|---|---|---|
| ждём ввод | `waitingKeyboard(template)` | `✖️ Отмена` → раздел |
| ошибка | `errorKeyboard(template)` | `🔁 Ещё раз` → `← Назад` → `🏠 Меню` |
| результат | `resultTemplateKeyboard(template, canAddCode)` | `➕` (если есть) → `🔁 Ещё раз` → `← Назад` → `🏠 Меню` |

Раздел определяет `sectionOf(template)`: `CS2_*` и `DOTA_*` → `section_codes`, всё остальное → `section_profile`.
Поэтому «Назад» с экрана CS2 ведёт в «Коды», а не в корень.

Исключения по делу:

- `cs2BanKeyboard()` остаётся на результате — тем же временем бана можно прогнать ссылку ещё раз;
- `friendVariantKeyboard()` — единственный экран с двумя равнозначными кнопками в ряд (ПК/Телефон);
- экран выбора CS2/Dota (`cs2Keyboard()`, `dotaKeyboard()`) показывается только как выбор экрана, а
  выбранный экран уже ждёт ввод с одной `✖️ Отмена`.

### 14.3 Результат — одно сообщение

`sendResult()` отправляет картинку с подписью и кнопками и удаляет экран ожидания. Подпись:

```
┌ 🎯 CS2 Fake Code
│ ✅ Готово · 3.4 с
```

Время берётся от `sendProgressMessage` (там же `sendChatAction('upload_photo')`) до готового буфера,
включая ожидание в очереди.

Готовый скриншот помечается `state.menuKind = 'result'` и больше не редактируется: раздел, открытый с
результата, приходит новым сообщением, картинка остаётся выше. Логотип-меню и экраны ожидания
(`menuKind: 'logo' | 'text'`) правятся на месте.

### 14.4 Шапка

`formatHint(title, text)` → `<blockquote><b>title</b>\ntext</blockquote>`. Две строки, без `🔗`.
Подпись экрана собирает `screenLabel(template, mode)`: `🫂 Ошибка добавления · Телефон`.

### 14.5 Прогресс

`⏳ Читаю профиль…` / `⏳ Собираю изображение…` / `⏳ Добавляю код …` / `⏳ Ставлю 30 Mins…`.
Никаких «Шаблон: …», «Очередь: …» — это ушло в лог и в `/health`.
