# Captcha на входе

Первый экран бота — не меню, а проверка. Простой пример, три варианта ответа, один верный. Пока
проверка не пройдена, ни одна команда и ни одна кнопка не работают: их просто нет.

## Как выглядит

```
┌ 🧩 Проверка
│ 16 + 12 = ?
│ Реши пример, чтобы войти.
[28] [25] [24]
```

Ошибся — пример новый, подпись меняется:

```
┌ 🧩 Проверка
│ 7 + 10 = ?
│ Неверно. Осталась одна попытка.
[19] [17] [13]
```

Вторая ошибка — пауза на 3 минуты:

```
┌ 🧩 Проверка
│ Слишком много попыток. Следующая через 3 мин.
[🔄 Проверить снова]
```

Все три минуты любое действие даёт только всплывающее уведомление — то же самое, без новых сообщений:

```
нажал любую кнопку в чате  → ALERT «Слишком много попыток. Следующая через 2 мин.»
нажал «Проверить снова»     → ALERT «Слишком много попыток. Следующая через 2 мин.»
написал текст или команду   → сообщение удалено, карточка паузы обновлена на месте
```

Прошёл — сразу меню, логотип на месте карточки проверки.

## Правила

- два слагаемых до 20, сложение или вычитание; ответы не различаются «по величине»;
- вариантов три, один верный; пример выдаётся заново после каждой ошибки, поэтому подобрать
  перебором нельзя — на каждый новый пример снова три варианта;
- `CAPTCHA_MAX_WRONG` (по умолчанию 2) ошибок → пауза `CAPTCHA_COOLDOWN_MS` (по умолчанию 180 000 мс,
  три минуты);
- **во время паузы любое действие — только всплывающее уведомление.** Нажатие любой кнопки в чате
  (хоть чужой, хоть «Проверить снова», хоть старой карточки) отвечает `answerCbQuery` с
  `show_alert: true`: сообщение в чат не уходит, экран не меняется. Текст и команды удаляются, а
  карточка паузы правится на месте — новых сообщений не появляется;
- после паузы счётчик ошибок обнуляется, пример новый;
- прохождение запоминается на диск: рестарт и деплой не заставляют решать заново;
- примеры живут только в памяти — старые кнопки после рестарта отвечают «кнопка устарела» и выдают
  новую карточку.

## Где живёт код

| файл | что |
|---|---|
| `src/captcha.js` | генератор примера, счётчик ошибок, пауза, файл состояния |
| `src/bot.js` | `bot.use(...)` первой в цепочке, `showCaptcha`, два action — ответ и «Проверить снова» |

Состояние: `data/captcha-state.json` на томе `./data:/app/data`:

```json
{
  "verified": { "123456789": 1732257000000 },
  "cooldowns": { "987654321": 1732257060000 },
  "wrong": {}
}
```

Запись идёт сразу после события, не по таймеру: контейнер могут погасить в любую секунду. В
`shutdown` последняя запись дожидается перед выходом.

## Настройки

```env
CAPTCHA_MAX_WRONG=2
CAPTCHA_COOLDOWN_MS=60000
CAPTCHA_BYPASS_IDS=123456789,987654321
CAPTCHA_FILE=/app/data/captcha-state.json
```

`CAPTCHA_BYPASS_IDS` — кому вход без проверки. Нужен владельцу, чтобы тестировать бота и не решать
пример после каждой чистой установки.

## Проверка

`/health` отдаёт:

```json
"captcha": { "verified": 12, "inCooldown": 1, "maxWrong": 2, "cooldownMs": 60000 }
```

## Что важно не сломать

- `bot.use(captchaGate)` стоит **первым** в файле, до `bot.start` и всех `bot.action`. Telegraf
  выполняет middleware в порядке регистрации: обработчик, зарегистрированный раньше гейта, обошёл бы
  проверку;
- ответ на капчу (`captcha_*`) гейт пропускает без проверки — иначе обработчик ответа не дойдёт;
- чужой текст до прохождения удаляется, чтобы в чате не копился мусор.
