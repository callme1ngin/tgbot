# Telegram HTML Bot - Оптимизированная архитектура

## 🚀 Компоненты оптимизации

### 1. **BrowserPool (`src/browser-pool.js`)**
- Переиспользование браузера и контекстов вместо запуска для каждого запроса
- Pool максимум 2 контекста по умолчанию (настраивается)
- Максимум 3 страницы на контекст
- Выбор контекста с минимальной нагрузкой
- Автоматическая очистка страниц

**Преимущество**: Вместо запуска браузера для каждого пользователя - 1 браузер на всех

### 2. **RequestQueue (`src/request-queue.js`)**
- Последовательная обработка запросов с лимитом параллельных операций (максимум 4 по умолчанию)
- Предотвращает перегрузку памяти при spike трафика
- Автоматическая обработка очереди

**Преимущество**: При 100 одновременных пользователях обрабатываются только 4, остальные ждут в очереди

### 3. **ScreenshotCache (`src/screenshot-cache.js`)**
- Кеширование скриншотов (максимум 100 кешированных элементов)
- TTL = 1 час по умолчанию
- Автоматическое удаление старых элементов при переполнении

**Преимущество**: Одинаковые запросы обрабатываются мгновенно из кеша

### 4. **Playwright оптимизация (`src/browser-pool.js`)**
```javascript
args: [
  '--no-sandbox',
  '--disable-dev-shm-usage',  // ← КРИТИЧНО для Linux
  '--disable-gpu',
  '--no-first-run',
  '--no-default-browser-check',
  '--disable-extensions'
]
```

**Преимущество**: На Linux сервере не использует /dev/shm, не загружает GPU и лишние расширения

## 📊 Ожидаемые улучшения

| Метрика | Без оптимизации | С оптимизацией |
|---------|-----------------|------------------|
| Запуск браузера | На каждый запрос | 1 раз при старте |
| Память на 100 пользователей | ~2-3 GB | ~300-500 MB |
| Время первого скриншота | 3-5 сек | 0.5-1 сек |
| Одинаковые запросы | Full обработка | <50ms из кеша |
| Параллельные запросы | Все одновременно | Контролируемо |

## 🔧 Конфигурация

Основные лимиты задаются через `.env`:
```bash
BROWSER_CONTEXTS=2
PAGES_PER_CONTEXT=3
MAX_CONCURRENT_REQUESTS=4
CACHE_SIZE=100
CACHE_TTL_MS=3600000
HTTP_TIMEOUT_MS=10000
MAX_REDIRECTS=3
FETCH_RETRIES=2
FETCH_RETRY_DELAY_MS=500
IMAGE_LOAD_TIMEOUT_MS=5000
IMAGE_RETRY_COUNT=1
SCREENSHOT_WIDTH=1920
SCREENSHOT_HEIGHT=1080
FRIEND_SCREENSHOT_WIDTH=1280
FRIEND_SCREENSHOT_HEIGHT=720
```

Итоговый максимум одновременно открытых страниц Chromium:
`BROWSER_CONTEXTS * PAGES_PER_CONTEXT`.

## 🧪 Мониторинг

Внутренний healthcheck доступен по `/health` на порту `PORT`/`HEALTH_PORT`.

## 📝 Логи

- `✓ Browser pool initialized with 3 contexts` - успешно инициализирован
- `✓ Cache hit for {url}` - скриншот взят из кеша
- `✓ Screenshot created for {url}` - новый скриншот создан

## 🐧 Linux сервер рекомендации

1. Установить зависимости для Playwright:
```bash
npx playwright install --with-deps chromium
```

2. Запустить бота:
```bash
npm start
```

3. Мониторить ресурсы:
```bash
watch -n 1 'ps aux | grep node'
free -h
```

## 🔍 Если проблемы с памятью:

1. Снизить `maxContexts` (3 → 2)
2. Снизить `maxPagesPerContext` (5 → 3)
3. Снизить `maxConcurrent` (5 → 3)
4. Добавить `--memory-pressure-off` в args Playwright

## 📈 Масштабирование

На 1 сервере (~2GB RAM):
- **Без оптимизации**: 20-30 одновременных пользователей
- **С оптимизацией**: 200-300 одновременных пользователей (зависит от размера шаблонов)
